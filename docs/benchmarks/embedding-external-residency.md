# 外置 embedding：扩展输入与驻留内存复测

结论：本轮不采用默认外置格式。初始化和峰值内存确有改善，但先前小语料观察到的常驻内存节省，在访问更分散的权重后基本消失。持续吞吐没有稳定改善，也没有充分证据断言各配置都无回退。继续优化时回到计算热点，不为这项收益改造生产缓存。

## 测量范围

- 沿用本机 Linux x64、ORT 1.30.0，线程 affinity 4/6/8/10，两个方向、普通/快速模式。仅外置 `Wemb`、`encoder_Wemb`、`decoder_Wemb` 中至少 1 MiB 的初始化权重；图节点与原始权重字节已断言一致。生产源码和模型未改。
- 固定 39 条语料、四轮交替、每块六遍全语料；1/2 个 ORT 线程、1/4 路并发。共 14,976 次计时翻译，逐 token 及累计 token 总数断言全部通过。每块仅一个会话存活并完整预热。
- 内存/初始化为独立 Node 进程，内嵌、外置、外置、内嵌顺序；每组两次取中位数。页缓存已热。RSS 包含 Node，不能直接与此前 C++ 探针绝对值对比。
- 本机有桌面及浏览器负载，CPU governor 为 powersave；固定 affinity 不等于独占核心或恒定频率。下面四轮结果有明显波动，不把数个百分点的变化视为已证实收益。未更改系统全局设置。

## 更分散的输入

- 普通模式另外增加 128 条确定性合成输入，每条 16 个合法范围内的 token ID，共 1,978 个不同源 token。两个方向分别运行内嵌/外置正反序对照，全部输出哈希一致。这是内存驻留及存储等价检查，不是自然语言翻译质量评估。
- 数据文件共 93.75 MiB。读取 `/proc/self/smaps` 检查权重映射实际驻留页；原语料下未访问的页不会全部计入 RSS。扩展输入后绝大部分权重页驻留。不是外置格式永久减少了模型权重字节。

## 普通模式精算转置检查

- 原图每步 Top9 之后的 FP32 精算写作 Gather → Transpose → MatMul → Add。尝试显式 Gemm(transB=1) 后，分别保存基线和候选的 ORT 优化图。
- 双向模型首步和 Loop 共四处，原图已被自动优化为 Gather → Gemm(transB=1)，显式转置不存在。候选与基线的投影输入、输出、属性和 Gather 输入全部一致。
- 已停止冗余耗时测试；没有用被中断的部分计时宣布收益，也没有修改生产转换器。此结论仅针对普通模式 Top9 精算，不替代之前快速模式转置实验。

## 限制与后续

- 不采用外置格式不等于否认启动收益；若以后明确优先降低启动峰值、延迟按需装载或跨进程共享物理页面，可重新评估，但仍需缓存原子发布、损坏恢复、侧文件生命周期等验收。
- 未测冷盘、内存压力、跨进程共享、完整服务重启/取消、其他硬件；扩展驻留实验仅测普通模式，未遍历全词表。这一轮没有生产改动，不 bump 版本或生成安装包。
- 本地脚本及模型在 `.tmp/external-embeddings/`、`.tmp/refine-transpose/`，JSON 保留完整结果及源脚本哈希。未提交完整可移植实验包。
