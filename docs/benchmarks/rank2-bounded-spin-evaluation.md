# 二维张量与有界线程自旋实验

结论：不修改生产默认值。二维布局保持本组隐藏向量逐位一致，但没有稳定的并发收益。有界自旋在原混合输入集的英译中测试中有延迟收益，同时增加低并发 CPU 开销；[仅正常请求复测](onnx-stages-normal-corpus.md)未稳健复现，不适合统一开启。

## 二维张量

- 在转换器副本中将恒为 1 的两个批维移除，使线性层使用二维张量；注意力的 head 维与归一化计算保持原顺序。两个方向、普通/快速模式的命名权重及量化权重逐字节断言一致。
- 优化后首步图仅少一个 Reshape，Loop 内节点数及算子种类计数不变。此前看似多余的维度并没有阻碍关键矩阵算子融合；另检查了 INT8 优化图，带 bias 的 MatMulIntegerToFloat / DynamicQuantizeMatMul 大多已融合 bias，未据此继续重复偏置融合。
- 39 条输入的普通/快速模式共 879,360 个投影前隐藏浮点值逐位相同。每个采样模型都与相应未插桩模型的 token 输出对照，避免插桩改变译文却未发现。样本一致不等于跨硬件或任意输入证明。

## 有界自旋

- 使用当前完整原模型及隔离原生扩展，保持 2 个 ORT 线程。候选只将 intra-op allow_spinning 开启，设 spin_duration_us 为 50 或 500、spin_backoff_max 为 4，并设置 session.force_spinning_stop=1；inter-op 自旋仍关闭。
- 最后一个并发 Run 返回时停止自旋；短时自旋试图让工作线程等待下一项小矩阵工作，减少睡眠/唤醒开销。持续时间是运行库校准的近似目标，不是硬实时上限。
- 六种排列各跑一轮，让 baseline / spin50 / spin500 在不同顺序出现，普通模式双向、1/4 并发，共 8,424 次计时翻译逐 token 对照通过。每块六遍全语料，累计 token 数也有断言。

## 调度证据

- 另做 baseline / spin500 / spin500 / baseline，单请求、双线程、同样六遍语料。用 Node process.resourceUsage（系统 getrusage 汇总）统计整个进程的主动/被动上下文切换。
- 最初逐线程 /proc 快照方案遇到运行中线程更替，断言终止了采集；该部分数据未用于下表。改用进程汇总后完整重跑，保留中断日志作为限制记录。

| 方向 | 方案 | 主动切换次数 | 被动切换次数 | 250 ms 空闲 CPU ms |
|---|---|---:|---:|---:|
| en_zh-Hans | baseline | 125243 | 289 | 0.59 |
| en_zh-Hans | spin500 | 368 | 542 | 0.12 |
| zh-Hans_en | baseline | 116894 | 257 | 0.36 |
| zh-Hans_en | spin500 | 370 | 566 | 2.15 |

工作线程少睡眠解释了收益，也解释了为什么单请求消耗更多 CPU。不能把减少切换次数等同于任意模型都加速；较大的中译英投影中收益较小。

## 采用边界

- 本机 Linux x64 / ORT 1.30.0，affinity 4/6/8/10，页缓存已热；桌面后台负载和动态频率未禁用。初筛、完整矩阵和调度探针各自独立，不能合并成单一置信区间。
- 自旋仅验证普通模式、2 线程，不泛化到 1/4/自动线程数、其他语言、其他 CPU 或 GPU。未测完整服务端排队、取消恢复、长时间热/功耗及多租户争用；不把低并发 CPU 成本隐去。
- 若以后明确优先英文单请求延迟，且接受额外 CPU 消耗，有界自旋是可继续验证的候选。当前没有新增开关或动态调参逻辑；没有生产代码、版本、安装包变更。
- 原始记录和脚本位于 `.tmp/rank2/`、`.tmp/bounded-spin/`，JSON 保留逐块指标、形状统计、权重检查和脚本哈希。未上传完整可移植复现包。
