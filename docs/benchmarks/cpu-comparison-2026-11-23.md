# CPU 性能对比：普通、Fast 与 LinguaSpark

> 最新 Waves 1–4 优化架构与 Intel Core i5-14400 本地 ABBA 实测见 [2026-11-23 双模式性能优化报告](performance-optimization-2026-11-23.md)；本文为同日 `Ryzen 9 9950X`（4 CPU 配额、3 GiB 内存）官方同口径三方复测。

2026-11-23 实测（替代 [2026-11-17 复测（v5.4.3）](cpu-comparison-2026-11-17.md)，历史记录见 [2026-11-16（v5.4.2）](cpu-comparison-2026-11-16.md) 与 [2026-11-14（v5.1.3）](cpu-comparison-2026-11-14.md)）。`v5.4.6`（提交 `299ece2`）在 Waves 1–4 全栈重构（紧凑 INT8 `SsruTranslate` 图、`N x K4` AVX-512 VNNI 内核、ragged C++ 编码器、`PcorePool` + `TeamBarrier` 持久化团队并行与混合连续批调度）基础上，新增 Linux cgroup `cpu.max` / CFS 配额感知以避免受限容器内过度创建线程及单核绑核竞争。Fast 模式在单请求、段落、长文与短句并发全部场景大幅领先 LinguaSpark（长文高出 **3.13–11.69 倍**，短句 8 并发高出 **60%–68%**）；普通模式（`--no-fast`）在不启用候选词表的前提下，单请求延迟比 5.4.3 再降 **32%–61%**、并发吞吐提高 **6%–92%**，长文吞吐反超 LinguaSpark 达 **1.82–4.47 倍**，热态 RSS 降至 **442.3 MiB**（峰值 **442.3 MiB**，降幅 22.7% / 41.6%）。本轮 27 条基准语料中，25 条短句与段落三方与 2026-11-17 完全一致（0 差异）；普通模式与 5.4.3 匹配 **26 / 27**（仅 `LONG_ZH-HANS` 第 5 句 `vehicle -> car`），Fast 模式匹配 **25 / 27**，LinguaSpark 匹配 **27 / 27**。Fast 相比普通模式仍可能增加误译。

结构化数据见 [cpu-comparison-2026-11-23.json](cpu-comparison-2026-11-23.json)。

## 测试条件

- AMD Ryzen 9 9950X，共享 Linux 主机（主机负载 `load1 <= 0.81`）；三方逐个运行，均限制 4 CPU 配额（cgroup v2 `400000 100000`）、3 GiB 内存、不使用交换空间、PID 上限 256、`nice=15`、`ionice idle`（与 2026-11-14、2026-11-16、2026-11-17 完全一致）。
- 使用相同 Mozilla 英中、中英模型和语料；关闭翻译缓存（`cacheSize=0`），经预转换与预热后按轮换顺序测试三轮，共 5193 次正式 CPU HTTP 请求（加预热共 5436 次），重复译文一致性检查全部通过。
- MTranServer 5.4.6（提交 `299ece2`），ONNX Runtime 1.30.0，容器启用 `tcmalloc`；普通模式与 Fast 均使用 `native-ssru`（后端 `packed-avx512vnni`，单算子线程，`PcorePool` 依 cgroup 配额约束为 4 核 / 4 并发槽位；普通模式使用全词表 `FullVocabQ4`，Fast 使用候选表 `ShortlistTable`）；LinguaSpark server 固定版本 `edd16a674b1484490a4a29d588dab9c1a191e6c3`，引擎固定版本 `269605c`，4 个 worker。
- 数值为三轮各自指标的中位数；延迟取每轮平均值，P95 取每轮最近秩百分位数。长文英译中 3244 字符，中译英 1516 字符，均为 32 句换行分隔。
- CPU 配额已逐例核对；Linux cgroup `cpu.max` 限制的是 CFS 周期配额，当配额小于宿主机可用核心数时 `PcorePool` 自动解除固定单核绑核交由内核公平调度。本记录仅包含 CPU 数据。

## 内存与首次使用

| 指标 | 普通模式 (5.4.6) | Fast (5.4.6) | LinguaSpark |
| --- | ---: | ---: | ---: |
| 双模型热态 RSS（MiB） | 442.3 | 505.6 | **313.0** |
| 测试期间峰值 RSS（MiB） | 442.3 | 512.9 | **313.1** |
| 启动至就绪（含预热，ms） | 979.0 | 781.0 | **285.7** |
| 首次英→中短句请求（ms） | 5.4 | **5.1** | 5.9 |
| 首次中→英短句请求（ms） | 3.0 | **2.2** | 4.9 |

热态内存方面，消除 `model.onnx` 双重加载及冗余 FP32 嵌入副本后，普通模式峰值 RSS 由 5.4.3 的 757.3 MiB 降至 **442.3 MiB**（降幅 **41.6%**），Fast 峰值 RSS 由 826.1 MiB 降至 **512.9 MiB**（降幅 **37.9%**）；启动至就绪分别缩至 **979.0 ms**（-23.5%）与 **781.0 ms**（-47.4%），首次短句请求在两个方向上已全部快于 LinguaSpark。若目录内仅有原始 Mozilla 模型文件、尚未生成 ONNX 缓存，首次离线转换耗时另计（本次预转换阶段实测：普通模式冷启动就绪 398.1 ms、首请求英→中 1954.3 ms、中→英 2355.0 ms；Fast 冷启动就绪 387.7 ms、首请求英→中 1841.6 ms、中→英 1968.9 ms）。内存取服务进程 RSS / HWM，不等于整个容器或系统的总占用。

## 结论与范围

- 对照组复现性：LinguaSpark 在本轮的短句 8 并发吞吐（1173.09 / 1335.55 req/s）、长文 4 并发吞吐（8.43 / 11.94 req/s）及 RSS（313.0 MiB）与 2026-11-14/16/17 基线吻合，宿主测量环境干净稳定。
- 普通模式对比 LinguaSpark：英→中短句（1.57 vs 3.56 ms，**2.26 倍**）、中→英短句（1.90 vs 3.43 ms，**1.80 倍**）、双向段落（4.52 / 5.43 vs 16.98 / 16.17 ms，**2.98–3.76 倍**）与 32 句长文单请求（30.58 / 50.79 vs 274.90 / 216.73 ms，**4.27–8.99 倍**）均大幅领先 LinguaSpark；并发场景下英→中短句 8 并发达 **1212.34 req/s**（高于 LinguaSpark `1173.09`），中→英短句 8 并发达 **1125.16 req/s**（较 5.4.3 提升 41.4%），双向 32 句长文 4 并发吞吐达 **37.73 / 21.73 req/s**，为 LinguaSpark 的 **1.82–4.47 倍**。
- Fast 对比 LinguaSpark：短句单请求延迟降至 **1.45 / 1.40 ms**（快 **2.45–2.46 倍**），短句 8 并发吞吐达 **1974.17 / 2134.26 req/s**（为 LinguaSpark 的 **1.60–1.68 倍**）；段落单请求 **3.79 / 4.22 ms**（快 **3.84–4.48 倍**）；32 句长文单请求快 **7.03–11.69 倍**，4 并发吞吐达 **48.83 / 37.41 req/s**（为 LinguaSpark 的 **3.13–5.79 倍**）。LinguaSpark 的常驻内存仍低于 MTranServer（313 MiB vs 442 / 506 MiB，差距已收窄至 1.41x / 1.62x）。

以上是共享主机 4 CPU / 3 GiB 受限容器下的中英双向测试，未测整机满载、其它语言或长期稳定性。各引擎重复输出一致不代表三方译文完全相同，也不代表翻译质量等价。
