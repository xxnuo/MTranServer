# CPU 性能对比：普通、Fast 与 LinguaSpark

2026-11-14 实测。Fast 的段落和长文性能更好，LinguaSpark 的短句高并发吞吐更高、内存更低。普通模式优先保证翻译准确性；本轮未重新评估翻译质量，Fast 仍可能增加误译。

## 测试条件

- Ryzen 9 9950X，共享 Linux 主机；三方逐个运行，均限制 4 CPU 配额、3 GiB 内存、不使用交换空间，低调度优先级。
- 使用相同 Mozilla 英中、中英模型和语料；关闭翻译缓存，经预热后轮换顺序测试三轮，共 5193 次正式 CPU HTTP 请求，重复译文一致性检查通过。
- MTranServer 5.1.3，ONNX Runtime 1.30.0，普通和 Fast 均使用 native-async；LinguaSpark server 固定版本 `edd16a674b1484490a4a29d588dab9c1a191e6c3`，引擎固定版本 `269605c`，4 个 worker。
- 数值为三轮各自指标的中位数；延迟取每轮平均值，P95 取每轮最近秩百分位数。长文英译中 3244 字符，中译英 1516 字符，均为 32 句换行分隔。
- CPU 配额已逐例核对；rootless 环境未委派 cpuset，不能将配额理解为独占四个物理核心。本记录仅包含 CPU 数据。

## 单请求延迟

单位 ms，越低越好。

| 场景 | 普通模式 | Fast | LinguaSpark |
| --- | ---: | ---: | ---: |
| 英→中短句 | 4.14 | 3.81 | **3.79** |
| 中→英短句 | 5.53 | 3.46 | **3.29** |
| 英→中段落 | 15.77 | **13.96** | 17.31 |
| 中→英段落 | 23.15 | **14.89** | 16.88 |
| 英→中长文（32 句） | 91.10 | **52.96** | 279.44 |
| 中→英长文（32 句） | 151.22 | **72.57** | 219.41 |

## 结论与范围

Fast 长文单请求比普通模式快约 1.72–2.08 倍，比 LinguaSpark 快约 3.02–5.28 倍。LinguaSpark 短句 8 并发吞吐比 Fast 高约 25%–29%。英译中短句单请求两者基本持平，不能把约 0.02 ms 的差异解读为稳定优势。

以上是共享主机受限资源下的中英双向测试，未测整机满载、其它语言或长期稳定性。各引擎重复输出一致不代表三方译文相同，也不代表翻译质量等价。
