# 连续投影组批、到达时间与并发基线

结论：连续补位在排队负载下仍有吞吐和延迟收益，但不能替换默认路径。加入现有原生并发基线后，收益比先前单工作线程对照更保守；低负载仍有退化。

## 对照方法

- 沿用已验证的分步图和官方 ORT 1.30.0；请求结束后立即记录完成、释放状态并补入新请求，不再等固定搭档结束。没有人为等待以凑齐 batch。
- 全模型基线直接调用原生 ORT，共享同一个会话；对照 1、2、4 个工作线程。连续版每工作线程最多处理两条请求，两个线程最多四条在途请求，四个分步会话均共享。
- 单核试验和双核试验各四轮交替；每段两个完整语料遍历（英文 40 次、中文 38 次请求）。双核主对照固定两个物理核心，比的是四请求并发的完整模型与两线程、四请求在途的连续组批，ORT 内部均单线程。
- 突发：所有请求同时入队。低速：间隔为单工作线程校准平均耗时的两倍。高压：单核间隔为平均耗时 0.8 倍，双核为 0.4 倍。每组对照用相同到达时间，不让前一请求的耗时决定下一请求何时发送。
- 同步 API 调用、真实推理、真实睡眠重放到达时间；没有 HTTP、网络和外部客户端。这是原生调度实验，不能称为服务压测。
- 每段记录请求到达、开始、完成时刻，校验唯一完成和时间顺序；p95 含排队时间，另保留排队与运行部分。每段样本数有限，不是生产 p95。

## 排除的回退策略

试过“队列只有一条请求时同步跑完整模型，否则组批”。在单核英文低速测试中，相对双工作线程完整模型，其 p95 中位数恶化约 90%：同步长请求阻塞了后来的短请求。这个简单策略不能采用。若后续做回退，需要保留现有并发能力，不能退化成单工作线程。

## 正确性与取消

- 两组正式对照共 6,552 次计时翻译逐 token 对照通过。动态到达和线程调度会改变请求配对，仍未观察到输出差异；这不是所有输入数值等价的证明。
- 扩展语料共 125 次输入（含重排重复和 8 条构造用例）。用 ASan/UBSan 版本测试共享会话多线程、未进入推理的取消、生成两个 token 后取消，并在同进程继续正常推理验证恢复。未取消请求完整输出一致，取消请求验证输出前缀；每条请求恰好一个终态。
- 取消是测试器按请求编号和生成步数注入，尚未接入真实 AbortSignal、HTTP 断开或外部取消消息。也未覆盖运行库抛错后的逐请求隔离与持续服务。
- 插桩测试器未报告越界或未定义行为；LeakSanitizer 仍报告之前最小 ORT 环境程序也能复现的 14 字节分配未释放。运行库本身未插桩，没有运行线程竞态检测，不能称为所有内存/并发检查通过。

## 剩余门槛

1. 低负载中文的中位延迟增加约 15%；需解决低负载路径及公平调度后再考虑默认采用。
2. 需要单独测量会话初始化和驻留内存；分步模型重复持有权重，当前计时把所有对照会话都加载在同一进程，不能据此比较部署内存。
3. 分步图仍来自本机已优化图。需查清原图拆分后数值变化的原因，形成可维护、跨机器的生成方式。
4. 仍缺真实 HTTP、取消/错误隔离、长时压力、更多语料、其他 CPU 和语言对的验收。

生产代码、版本、默认配置均未更改。原型与原始时间线位于本地 `.tmp/continuous-batch/`；持久数据为 `continuous-projection-batch.json`。记录保留正式双核测量源码和后续验证源码的哈希；早期单核版本是辅助证据。临时源码、模型和完整时间线未上传，此记录不是可移植复现包。
