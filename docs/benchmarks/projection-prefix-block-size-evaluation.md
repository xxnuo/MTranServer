# 公共候选投影与 INT4 量化块实验

结论：保持现有投影实现和 64 元素 INT4 块。公共候选拆分未显示足够收益；128 元素块没有稳定的双向加速，256 明显退化，32 也有小幅退化。没有生产代码或精度配置变更。

## 公共候选投影

- 当前两组模型的 lexical frequent prefix 为 50，byte fallback ID 为 7–262。因此这些模型通过现有 Shortlist 生成的候选至少包含连续 0–262；实测 39 条输入的连续前缀更长。
- 原型把前 256 个词的 FP32 投影矩阵与 bias 设为常量，其余候选仍按请求 Gather/Transpose，最后按原顺序拼接 logits。词表、权重数值、ArgMax 顺序没有主动改动；导出时逐元素核对常量矩阵的原始 float32 位。
- 只在输入确实具有完整 0–255 前缀且还有尾部候选时运行，并对全部测试候选做断言。它不是适用于任意 candidate_ids 的通用 ONNX 模型。若采用必须补齐契约和其他词表兼容；初筛没有收益，因此未做这项扩展。
- 增加了投影分支和拼接工作；预先固定公共权重没有带来稳定的双向吞吐收益。两组各 20/19 条输入的最终 token 均与原模型一致，但没有宣称中间 logits 逐位相同。

## INT4 量化块

- 分别测试 32、128、256 元素块，基线为 64；仍是 4-bit 权重、accuracy_level=4、Top9 候选和原 FP32 精算。只重建投影 Q4 数据、scales、维度及 MatMulNBits 的 block_size 属性。
- 通用块量化器由当前量化函数派生，先在 block=64 时重建并断言 packed/scales 与现有模型字节一致，再生成候选，避免把量化器复现错误当成方案差异。
- 更大的块不必然更快：缩放数量减少，但实际耗时取决于所用内核和运行形状。本轮只记录整句测试结果，未以调用栈证明退化的具体指令原因。
- 改变块大小会改变近似计算，不是无损代数改写。原 39 条输入在三个候选中都逐 token 一致；随后加入重复原句、引号、日期数字、前缀提示、与下一句拼接等上下文变体，总计 234 个输入，每个候选均与当前基线逐 token 一致。
- 这 234 个输入用于输出兼容性检查，包含原 39 条，不是 234 个独立人工参考译文。没有 BLEU/COMET、人工盲评或跨语言质量结论，不能把未观察到差异称为任意输入质量无损。

## 初筛结果

- Linux x64、ORT 1.30.0、固定 CPU4、单线程、单请求；页缓存已热，每块完整预热。每个配置四轮正反序交替、每块六遍原 39 条语料中对应方向的全部输入。
- 共 7,488 次计时翻译，逐 token 与累计 token 数断言通过。正数表示候选更快；下表使用四轮配对中位数，不能与“两个耗时中位数的比值”混用。
- 桌面负载及动态频率未禁用。小幅变化可能来自波动；不把短块初筛当作并发服务性能验收。

## 未采用与限制

- 公共候选原型未取得足够收益，不增加额外输入契约、特化模型或候选权重缓存。候选缓存的真实跨请求命中率也尚无生产证据，不能用反复跑相同语料的命中率替代真实流量。
- 已测块大小没有达到修改默认格式的条件；保留现有 64。这里没有断言其他块大小、其他 CPU/运行库或其他模型一定无收益。
- 未测这些候选的多线程/并发矩阵、完整服务生命周期、其他硬件或独立质量语料。因为初筛无足够收益，没有引入生产兼容代码、版本升级或新构建产物。
- 实验模型与脚本保留在 `.tmp/shortlist-common/`、`.tmp/projection-blocks/`、`.tmp/projection-block32/`；JSON 记录原始块计时、验证结果和脚本哈希。未上传完整可移植复现包。
