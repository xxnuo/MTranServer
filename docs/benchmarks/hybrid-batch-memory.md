# 双工作线程回退与分步模型内存成本

结论：当前方案不采用为默认后端。完整模型回退解决了部分低负载问题，但双工作线程仍限制高压下的并发；同时保留完整模型与分步模型的驻留内存明显增加。暂不继续增加调度策略，下一条低成本实验是检查能否用 ORT 原生接口共享重复权重。

## 回退机制与复测

- 两个工作线程共享完整模型和分步会话。线程空闲且队列只有一条已到达请求时，直接调用完整模型；有多条请求时继续投影组批。完整模型调用仅阻塞当前工作线程，不再阻塞全部请求。
- 两个物理核心、ORT 内部单线程；比较完整模型 2/4 工作线程、连续组批、带回退组批四种方案。每种到达模式做六轮交替，每段两个完整语料遍历。
- 到达模式沿用前次实验：突发、低速、高压。相同轮次的请求数量、输入、到达间隔相同；所有计时输出均与原模型参考逐 token 对照。
- 共 5,616 次计时翻译输出一致。低速下，英文每段 40 条、中文每段 38 条全部使用完整模型，确认回退实际生效。

下表相对四工作线程的完整模型，使用六轮配对中位数；延迟负值代表改善。

| 方向 | 到达模式 | 吞吐变化 | p50 延迟变化 | p95 延迟变化 |
|---|---|---:|---:|---:|
| en_zh-Hans | 突发 | +7.2% | -14.9% | -16.0% |
| en_zh-Hans | 低速 | -0.6% | +1.5% | -6.8% |
| en_zh-Hans | 高压 | -4.4% | -9.1% | +46.1% |
| zh-Hans_en | 突发 | +28.7% | -29.8% | -27.6% |
| zh-Hans_en | 低速 | +0.2% | +6.4% | +1.4% |
| zh-Hans_en | 高压 | +1.7% | +24.6% | -6.7% |

英文高压的六轮吞吐全部低于四工作线程基线，p95 全部更差，中位数约 +46%。中文突发收益波动很大（吞吐比约 0.79–2.22），不能宣传中位数为稳定加速。原始范围见 JSON。

回退并非通用解法：本原型在两个长请求同时进入完整模型后，短请求仍只能等待工作线程空闲；四工作线程基线没有同样的两请求限制。下一步若继续调度研究，必须对齐这个并发能力，不能依赖只看平均吞吐的测试。

## 独立进程内存测试

- 每次启动新原生进程，只加载被测方案；不再把全部对照模型放在同一进程。每方向按 baseline/split/hybrid/hybrid/split/baseline 顺序测量。
- baseline 仅完整模型；split 仅四个分步/投影会话；hybrid 同时保留完整模型及四个分步会话。所有方案共用同一 ORT 版本和单线程设置。
- 记录 ORT 环境创建后的 RSS、会话初始化后的 RSS、两轮完整语料推理后的 RSS、进程峰值 RSS 和初始化耗时。hybrid 分别运行完整和组批路径，确保两条路径都预热。
- 完整模型首先生成当前 token 参考；其他进程读取并验证。12 个进程共校验 624 次翻译，重复参考文件哈希不变。OS 页缓存已热，初始化时间不是冷磁盘启动时间。

下表为两次新进程测量的中位数，MiB = KiB/1024。

| 方向 | 布局 | 预热后 RSS | 峰值 RSS | 初始化耗时 ms |
|---|---|---:|---:|---:|
| en_zh-Hans | baseline | 177.7 | 203.4 | 194.3 |
| en_zh-Hans | split | 284.6 | 330.3 | 348.7 |
| en_zh-Hans | hybrid | 416.5 | 462.6 | 505.6 |
| zh-Hans_en | baseline | 186.1 | 256.9 | 221.8 |
| zh-Hans_en | split | 494.2 | 585.4 | 465.4 |
| zh-Hans_en | hybrid | 633.5 | 725.0 | 684.9 |

这是原生测试进程的实际驻留内存，不是 ONNX 文件大小，也不是包含 HTTP/Node 层的完整服务内存。它没有覆盖超长输入、多语言同时加载或多核并发的峰值。当前分步会话没有共享初始化权重或预打包缓存，因此结果不能代表应用共享机制后的下限。

## 下一条验证与边界

- 当前 ORT C API 提供 AddInitializer 和共享预打包权重容器。可以先在临时模型上验证共享重复权重是否降低内存、是否保持输出，不需要继续扩大调度实现。尚未运行该实验，不能声称已有内存收益。
- 若共享后成本仍偏高，或需要明显扩大维护面，停止这条默认后端路线。高负载特定部署是否值得采用，应单独评估。
- 新回退路径尚未做外部取消和错误隔离验收；本轮没有重新运行 sanitizer，不沿用之前连续组批原型的检查结果作为新路径已验收的证据。
- 生产代码、模型格式、默认设置和版本未更改。没有执行发布构建。

数据见 `hybrid-batch-memory.json`。本地原型和时间线位于 `.tmp/hybrid-batch/`，内存测试器和参考 token 位于 `.tmp/batch-memory/`；临时制品未上传，此记录不是完整可移植复现包。
