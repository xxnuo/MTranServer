# ONNX 原生 SSRU 解码器

5.3.0 新增实验性 Fast CPU 后端，默认关闭。使用 `MT_FAST=true MT_NATIVE_SSRU=1` 启用，实际选中后运行时标识为 `native-ssru`。不支持插件或初始化失败时继续使用普通 ONNX；运行故障回退原 Fast 图。

编码器和每层 K/V 准备保留 ONNX；首步到 EOS 的完整解码循环由原生执行器管理。线性层在支持的 x86 主机使用独立编译、运行时检测的 AVX-VNNI Gemmology 预打包内核，其他形状或主机保留 InvokeOp。Sin、Sigmoid、归一化及 Attention 使用 ORT 数学实现，Attention QK 缩放匹配优化图的 FusedMatMul。没有逐 token 调用多个 Session::Run。

## 正确性与质量

早期标量数学版本出现否定反转和事实错误，未通过验收。逐阶段核对发现微小非线性／归约差异经动态量化边界放大；只看平均 chrF++ 无法发现这类问题。该版本性能不作为最终成果。

最终数学路径在开发集每方向997条、正式保留集每方向1012条上逐 token 与原 Fast 相同，均生成 EOS。保留集使用独立 FLORES-200 参考译文，chrF++／BLEU 如下：

| 方向 | 样本 | Fast／原生 chrF++ | Fast／原生 BLEU | token 一致 |
| --- | ---: | ---: | ---: | ---: |
| 英→中 | 1012 | 25.1116 / 25.1116 | 38.9804 / 38.9804 | 1012 |
| 中→英 | 1012 | 54.7841 / 54.7841 | 27.4217 / 27.4217 | 1012 |

这证明当前模型、运行库和语料上的一致性，不能推广为任意输入、模型或平台的逐位等价。

## HTTP 短句对照

Intel i5-14400、Linux x86_64、Node26.13.1、ORT1.30.0。相同来源的模型／词表／lexicon，缓存与 GPU 关闭，预热后三轮轮换方案。Node HTTP 长连接客户端计时包含请求与排队；旧 urllib 客户端出现约71rps瓶颈，其数据已排除。

所有引擎允许使用整机16个逻辑CPU。MTran 内部每次 Run 为1线程，UV线程池／并发上限16；LinguaSpark为16 worker。相同 affinity 不代表内部调度相同。每方向仅10条独立短句，重复次数不是新增独立样本。

| 指标 | 原 Fast | 原生 SSRU | LinguaSpark |
| --- | ---: | ---: | ---: |
| 英→中单句平均延迟 ms | 8.49 | 6.87 | 11.05 |
| 中→英单句平均延迟 ms | 6.76 | 6.03 | 10.23 |
| 英→中8并发请求/秒 | 406.20 | 548.90 | 485.70 |
| 中→英8并发请求/秒 | 491.55 | 633.31 | 486.70 |

原生 SSRU 短句8并发吞吐比 Fast 高约29%–35%，比 LinguaSpark 高约13%–30%。未达到所有场景吞吐翻倍的研究目标。各轮延迟、P95、RSS、运行时选择及哈希保存在同名 JSON；完整逐请求数据在本地 `.tmp/native-ssru/`。

## HTTP 长文对照

每方向一篇32句文本，每轮单请求重复6次，4／8并发重复24次；三轮均完成且输出与 Fast 相同。这里的重复请求用于负载测试，不是独立语料样本。

| 指标 | 原 Fast | 原生 SSRU | LinguaSpark |
| --- | ---: | ---: | ---: |
| 英→中单请求平均延迟 ms | 130.64 | 108.03 | 478.56 |
| 中→英单请求平均延迟 ms | 170.96 | 138.16 | 565.79 |
| 英→中8并发请求/秒 | 8.12 | 10.85 | 5.43 |
| 中→英8并发请求/秒 | 6.46 | 8.39 | 4.41 |
| 英→中8并发 P95 ms | 1052.33 | 794.74 | 2021.30 |
| 中→英8并发 P95 ms | 1328.51 | 985.17 | 2503.89 |

长文8并发吞吐比 Fast 高约30%–34%，为 LinguaSpark 的1.90–2.00倍。单请求延迟为 LinguaSpark 的约四分之一，这不是饱和吞吐四倍。每项数值取三轮统计量的中位数；P95为各轮请求延迟线性插值95分位数的中位数。

短句测试结束时进程 RSS 三轮中位数：Fast 691.79 MiB、原生725.75 MiB、LinguaSpark 191.76 MiB。长文测试分别为811.30、775.00、772.54 MiB；各轮峰值最大值分别为850.57、1380.44、828.84 MiB。RSS是整个进程在所有场景结束后的采样，不是单个场景或单份权重；尚未拆分raw／quantized／packed／workspace归属。原生路径的峰值内存成本不能忽略。

长文、短句与打包验证使用相同最终main／addon／worker哈希。长文运行中仅为脚本增加首次使用计时记录，未改变压测负载；其脚本哈希代表完成时文件，首次使用另行测试。共享工作站没有独占CPU预约，结果应结合三轮明细及其他机器复测评估。

## 首次使用

另开进程轮换测试三轮，复用已准备的 Fast 模型缓存，不清空操作系统页缓存。MTran 就绪接口约0.35秒返回，但这不代表模型已加载；LinguaSpark 启动策略不同，不能只比较端口就绪时间。

| 首次请求延迟，三轮中位数 ms | 原 Fast | 原生 SSRU | LinguaSpark |
| --- | ---: | ---: | ---: |
| 英→中 | 5583.2 | 5903.7 | 25.9 |
| 中→英 | 6524.8 | 6802.8 | 25.9 |

首次请求包含惰性模型初始化和现有后端探测。原生第一轮还要生成自定义图，分别7418.5／8284.4 ms；后两轮已有该图缓存。这项优化针对预热后推理，尚未解决 MTran 首次使用数秒的成本。

## 构建与边界

完整测试237项及类型检查通过。原生核心及预打包内核通过标量参考、边界、异常恢复、并发及 ASan/UBSan 验证；未对发行 ORT 共享库插桩。零逐 token 分配检查仅覆盖核心标量路径，不能用于声称 ORT 适配层零分配。

Node 和 library 构建及 tarball 解包导入／真实翻译通过，tarball 包含预编译插件及 MIT/BSD 许可证。npm 包不提供原生源码自包含重编译。Docker 使用相同正式构建入口，最终镜像已确认插件能力、许可证与真实 `native-ssru` HTTP 请求；验证构建仅用临时文件切换包下载镜像并引入已有 CA，未关闭 TLS 校验，项目 Dockerfile 保留官方源。

仅实测本机 Linux x86_64 AVX-VNNI。ARM64、macOS、Windows及无VNNI机器没有本轮真机性能结果。新增图缓存与额外权重／调用缓冲增加内存；默认保持关闭，不能用局部吞吐改善推广为通用默认收益。
