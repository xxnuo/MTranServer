# 候选 ID 上限的速度与独立质量初筛

结论：不采用这项启发式裁剪。两个上限在开发集上均有明显质量下降，中译英新增生成失败，速度没有足以支持继续验收的稳定优势。否决依据是人工参考译文指标和失败情况，不是输出必须与基线逐字相同。

## 原型与语料

- 当前二进制 lexical 字典的候选按 token ID 排序，没有概率字段，故不能把前 N 项解释为概率 TopN。本原型明确限制候选 token ID，而非伪称按翻译概率剪枝。
- 在现有快速模式候选生成后，只保留 ID <8192 或 <4096 的项；当前模型的全部字节回退 ID 均在此范围内，保留 EOS，词表共享时保留原候选中出现的源 token 以支持复制。按现有规则补齐到 8 的倍数，再排序。没有改模型权重、源分词或解码上限。
- FLORES-200 开发集，每方向 100 个 id % 10 == 0 的输入，逐条核对 source/reference 与本地归档的原始 dev 文件。保留 devtest，不在质量已明显失败的候选上继续消耗测试集。
- baseline / cap8192 / cap4096 / cap4096 / cap8192 / baseline，共每方向六块；固定 CPU4、单线程，各策略的重复输出一致。计时仅包含原始 session.run，未包含候选生成、分词、HTTP 或排队；首条分配、动态频率和桌面负载可能影响计时。不能据此宣称服务吞吐改善。

## 结果

| 方向 | ID 上限 | 尝试调用吞吐变化 | chrF++ 差值及配对 95% CI | BLEU 差值 | 失败 基线/候选 |
|---|---:|---:|---|---:|---:|
| en_zh-Hans | 8192 | +0.51% | -5.883 [-9.173, -4.189] | -9.109 | 0 / 0 |
| zh-Hans_en | 8192 | -20.54% | -9.870 [-11.982, -8.085] | -9.525 | 0 / 1 |
| en_zh-Hans | 4096 | -6.06% | -8.089 [-11.633, -6.242] | -13.001 | 0 / 0 |
| zh-Hans_en | 4096 | +12.89% | -14.980 [-16.991, -13.046] | -13.762 | 0 / 1 |

- 到生成上限且无 EOS 的输出计为失败，并以空译文计入质量分数。中译英候选各有 1/100 失败，不是生产错误率估计；存在失败的调用计时不能等同于成功翻译吞吐。
- SacreBLEU 2.5.1：chrF++ char6/word2/beta2；BLEU 英译中为 zh、中译英为 13a tokenizer。chrF++ 配对 bootstrap 1,000 次、seed=20261113；完整 signature、点估计和 CI 在 JSON。
- 数据少且主题可能相关，置信区间并不覆盖所有域和所有评估偏差。本组明显的参考指标损失已足以停止初筛，不把“允许译文变化”理解为接受任意质量下降。

## 边界

- 未做人工语义盲评、多线程/并发、完整 997 条开发集或最终测试集评估；未验证其他语言、词表或硬件。ID 排序也不是通用频率或翻译概率排序。
- 生产实现、候选策略、版本与包均未改变。原型和逐句输出保留在 `.tmp/candidate-cap/`，提交聚合指标、原始块计时、数据与模型哈希；不上传原始平行语料。
